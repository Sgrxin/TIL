# 2026-11-23 · RAG 效果评估：怎么知道你的检索好不好

RAG 链路讲了切分、SSE、余弦、rerank——今天补最后一环，也是面试最容易露怯的一环：**你怎么证明你的 RAG 好用？**

## 没有评测集，一切优化都是玄学

很多人调 RAG 的方式是"改个参数→自己问两句→感觉变好了"。这不叫优化，叫迷信。正确的起点是建一个**评测集**：几十条真实问题 + 每条标注"哪个 chunk 是标准答案出处"。

## 两个核心指标

**1. 检索命中率（Recall@k）**：标准答案 chunk 是否出现在 top-k 里。
> 检索不中，后面模型再强也是白搭——垃圾进垃圾出。这是 RAG 评估的第一指标。

**2. 回答忠实度（Faithfulness）**：回答内容是否**只基于检索到的材料**，有没有自由发挥。
> 命中了但答案瞎编，等于没检索。人工抽查或用另一个模型对照材料打分都可以。

## 迭代闭环

```
建评测集 → 跑基线分数 → 改一个变量（chunk/overlap/top-k/加rerank）→ 重跑对比
→ 分数升了才合入，降了就回滚
```

一次只改一个变量，和做实验一模一样。我调 400/80 切分参数时就是按这个流程走的。

## 面试一句话

> RAG 优化不能靠感觉：先建带标注的评测集，用检索命中率管"找没找到"、忠实度管"编没编"，改任何参数都重跑对比——有数字才有迭代。

## 延伸

工业界还有 RAGAS 这类现成评估框架（自动算命中率/忠实度/答案相关性）；笔试里能说出"评测集+双指标+单变量迭代"这三件套，就已经超过大多数候选人了。
